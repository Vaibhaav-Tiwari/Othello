How the canvas thinks.

A tour of the internals: one HTML file, no build step, no dependencies. Board state is a plain 2D array, the DOM is redrawn from it after every move, and the opponent is a small minimax search with alpha-beta pruning.

II · Data

State model

The board is an 8×8 array of null | "B" | "W". startBoard() places the four centre discs (W on D4/E5, B on E4/D5). All game state lives in a handful of module-level lets:

VariablePurpose
boardThe 8×8 grid
turnSide to move, "B" or "W"
history{r, c, p, flips} per move — powers undo and the move chronicle
validCacheLegal moves for turn, recomputed on every render
modeai-black (you play Black), ai-white, or 2p
diffeasy / medium / hard (Muse / Scholar / Oracle)
aiBusy, gameOverInput guards
showHints, soundOn, fxOnUI toggles

Squares are named with moveName(r,c) → file letter + rank, e.g. D3.

III · Rules

Game logic

Everything rests on one function. For an empty square, flipsFor walks each of the 8 directions in DIRS, collecting opponent discs until it hits one of the player's own. A ray counts only if it's non-empty and ends on a friendly disc.

function flipsFor(b,r,c,p){
  if(b[r][c]) return [];
  const out=[];
  for(const [dr,dc] of DIRS){
    let rr=r+dr, cc=c+dc; const line=[];
    while(inB(rr,cc) && b[rr][cc]===opp(p)){ line.push([rr,cc]); rr+=dr; cc+=dc; }
    if(line.length && inB(rr,cc) && b[rr][cc]===p) out.push(...line);
  }
  return out;
}
validMoves(b,p)

Scans all 64 squares; any with a non-empty flip list is legal.

applyMove(b,r,c,p)

Places the disc and flips in place; returns the flipped coordinates (or null if illegal).

countDiscs(b)

Returns {B, W, empty} for the score meter and end screen.

Passing & game end

advance() switches sides. If the new side has no move but the other does, it plays a pass sound and hands the turn back. If neither side can move, endGame() counts discs and shows the result modal. A manual Pass button exists, but it's rejected while legal moves remain.

Undo

Each history entry stores its flips, so undo() just reverses them: clear the placed square and give each flipped disc back to the opponent. In AI modes it pops two plies so control returns to the human, then sets turn from the last remaining entry (or the chosen first player).

IV · Sequence

Game flow

click cell→onCell→doMove→render + flip anim→ 620ms →advance→aiPlay?

onCell ignores clicks while the AI is thinking, when it's the AI's turn, or after the game ends. Illegal clicks trigger a low buzz and a shake animation via the Web Animations API. aiPlay() waits a random 420–920 ms (so the engine looks like it's “dreaming”), calls engineMove, then goes through the same doMove path as a human move.

Changing mode or first player calls newGame(). If the engine moves first, it starts playing right away.

V · The Oracle

AI opponent

engineMove(board, player, diff) runs a depth-limited minimax with alpha-beta pruning, always scored from the root player's side.

LevelKeyDepthNotes
Museeasy1 ply35% of the time, plays a random legal move
Scholarmedium3 pliesDefault
Oraclehard5 pliesAlso powers the “Hint a move” button

Evaluation

evaluate(b, p) combines three terms:

score = positional × 4  +  (myDiscs − oppDiscs) × 2  +  (myMobility − oppMobility) × 12
positional = Σ W8[square] for own discs − Σ for opponent discs, ±250 per held corner

The W8 weight table rewards corners and edges and punishes the X- and C-squares next to empty corners:

Search details

  • Move ordering: candidates are sorted by square weight, then by number of flips, so corners get searched first and pruning kicks in earlier.
  • Passes: if the side to move has no moves, the search recurses for the opponent at depth − 1. If neither side can move, it's a leaf.
  • Copies: each child gets a fresh b.map(r => r.slice()), so there's no make/unmake bookkeeping.
  • The search runs synchronously on the main thread inside a setTimeout. At depth 5 that's still quick enough on this board size.
VI · Pigment

Rendering

Rendering is immediate-mode DOM. render() clears #board, which is a CSS grid, and rebuilds 64 .cell divs. Each one gets a .disc.black/.white child, or a .hint dot on legal squares (.capture when the move flips 3 or more). It then refreshes counters, the score meter, turn labels and the move chronicle.

Discs

Pure CSS: radial gradients give the lacquered look. A placed disc plays a drop keyframe. A flipped disc first gets .flipping (rotateY(90deg)), then its colour class is swapped 140 ms + 28 ms × index later, so flips ripple outward one after another.

Particles

A <canvas id="fx"> laid over the board. burst() spawns gold/ink/terracotta/sage particles with gravity and decay, drawn by a continuous requestAnimationFrame loop. The canvas is resized to match the board on every render and on window resize.

Atmosphere

Fixed layers: a blurred, drifting radial-gradient “aurora”, SVG-noise grain, a vignette, and a giant vertical outlined word in the background. The board sits in a gilded frame on green felt.

The layout is a two-column grid (board + side panel) that collapses to one column below 980 px.

VII · Flourishes

Audio & extras

  • WebAudio sounds: tone() builds an oscillator and gain envelope on demand, with no audio files. sfx provides place, flip, bad, pass and win (a C-major arpeggio).
  • Hints: toggled with a button or the H key (ignored while a select or input has focus).
  • Chronicle export: “Copy” writes OTHELLO 1. B@D3 2. W@C5 … to the clipboard.
  • Self-test: selfTest() runs console.assert checks on page load: 4 opening moves, D3 flips one disc, flipping works, and the engine finds a move.
  • Deploy: static site. Netlify publishes the repo root and adds anti-framing and nosniff headers.
